## I. Introduction

The representation in 3D of a landscape is a critical aspect of modern mapping. For example, in times of space exploration, having a 3D representation of Mars is a prerequisite for its conquest.

Comparing various 3D representations of an area of high tectonic activity allows for a better understanding of these phenomena and their evolution, helping humanity prepare.

In this project, you will model 3D landscapes—whether imaginary or real.

*Note: FDF is short for 'fil de fer' in French, which means 'wireframe model'.*

## III. Common Instructions

- Your project must be written in **C**.
- Your project must adhere strictly to the **Norm**. Any norm error in bonus/mandatory files results in a grade of 0.
- Functions must not quit unexpectedly (`segmentation fault`, `bus error`, `double free`, etc.) except for undefined behavior.

- If your project permits `libft`, copy its sources and Makefile into a `libft` folder. The project's Makefile must compile `libft` before compiling the project.

### Project Description

Create a simple wireframe model representation of a 3D landscape by connecting points $(x, y, z)$ using line segments (edges).

### V.1 Rendering

- The program must represent the model using **isometric projection**.
- The coordinates of the landscape are stored in a `.fdf` file supplied as a command-line argument.

#### File Format Example (`42.fdf`)

```text

```

#### Coordinate Mapping

- **Horizontal position**: Abscissa ($x$-axis)
- **Vertical position**: Ordinate ($y$-axis)
- **Value**: Altitude ($z$-axis)

#### Execution

```bash
$> ./fdf 42.fdf
```

*Note: You may use helper functions from `libft` (such as `get_next_line()` and `ft_split()`) to parse file data cleanly. Assume input map files are properly formatted.*
